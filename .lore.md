* **@xmldom/xmldom override needs both floor and ceiling — open-ended range floats past plist compat**: getsentry/spotlight's pnpm override \`@xmldom/xmldom: >=0.8.13\` (open floor, added to patch a CVE while keeping plist@3.1.0 compat after the earlier plist>=3.1.1 override broke osx-sign) later floated to 0.9.10, whose parseFromString requires a mimeType arg that plist@3.1.0/app-builder-lib@26 don't pass — throwing 'DOMParser: mimeType undefined is not valid' and breaking build:mac (found in PR #1337, after PR #1335 bumped electron-builder 24→26). General lesson: blanket pnpm overrides need major-bounded ranges, not open floors (same fix pattern applied to brace-expansion in #1337).

* **APPLE\_API\_KEY raw DER lacks PEM armor — breaks Xcode 26 notarytool**: In getsentry/spotlight's build.yml, \`jq -r .private\_key\` on the APPLE\_API\_KEY secret extracts a raw base64 DER body with no PEM header/footer/line-wrapping. Key itself was valid — issue was purely missing PEM framing. Fix (PR #1334, commit 66d991e3): wrap the body with BEGIN/END PRIVATE KEY armor + 64-col folding, idempotently, in both build.yml locations. Verified end-to-end via CI run 29828172734 on macos-26-arm64 — notarization successful for both archs, DMGs produced. Follow-up PR #1335 (commit 43797cca) upgraded electron-builder 24.13.3→26.15.7, bumping bundled @electron/notarize to 2.5.0 so future notarization errors surface as real messages instead of being masked by JSON.parse SyntaxErrors.
